# Google Play release preparation

The Android application ID is `dev.solveit.solveit`; keep it stable to preserve installed workbooks. The current build targets Android API 36. The GitHub APK is for local installation and uses the existing local debug signing identity. It is not the Play upload artifact. A Play-installed app will have a different signing identity, so a user moving from the GitHub APK should export a workbook backup before uninstalling and then import it after installing from Play. On the import preview, select **Restore profile & study settings** to bring over the learner setup. AI consent and private runner credentials must be configured again.

The public privacy page is `https://looploom-coach-2026.web.app/privacy.html` and Settings links to it. Use the copy and screenshot plan in [the store listing draft](PLAY_STORE_LISTING.md). Verify the Data safety answers against the final SDKs and Play-installed build before submission.

## Create a Play upload bundle

1. A separate upload keystore can be created locally with `./scripts/create-play-upload-key.ps1`. The script refuses to overwrite an existing key, saves it under ignored `.local/play-upload`, and encrypts its random password for the current Windows user. **Before Play submission, back up the keystore and record the password in a separate password manager.** Run `./scripts/show-play-upload-recovery.ps1 -Reveal` yourself in a private PowerShell window to read it; never paste its output into chat or Git. The Windows-encrypted credential file alone cannot be recovered on a different computer or Windows account. Google Play App Signing manages the final app signing key, but you must retain your upload key or complete Google's key-reset process if it is lost.
2. Build with `./scripts/build-play-bundle.ps1 -Flutter 'path/to/flutter.bat'`. It temporarily loads the local upload credentials into the build process and clears the environment variables afterward. Alternatively set `LOOPLOOM_UPLOAD_KEYSTORE`, `LOOPLOOM_UPLOAD_STORE_PASSWORD`, `LOOPLOOM_UPLOAD_KEY_ALIAS`, and `LOOPLOOM_UPLOAD_KEY_PASSWORD` in your own terminal and run `flutter build appbundle --release --dart-define-from-file=firebase.ai.json` from `apps/solveit`. Do not commit passwords or send them in chat.
3. The bundle task fails when the upload key is missing. The resulting `apps/solveit/build/app/outputs/bundle/release/app-release.aab` is the candidate for Play internal testing, not a production rollout.
4. Register the Play App Signing SHA-256 certificate fingerprint in Firebase project settings for the same Android app. Keep Play Integrity App Check enabled. Test Gemini through a Play internal test install before a wider release.
5. In Play Console, finish the store listing, privacy policy, Data safety declarations, content rating, testing requirements, and any account or payment policies that apply at submission time. Upload to internal testing first, then verify installation, app links, offline practice, backup, code runner configuration, and AI consent on real devices.

The current sideloaded APK may fail App Check's default Play-recognized verdict. Changing the production policy to allow outside-Play builds is a separate security decision; the web PWA and authored offline review remain usable while it is undecided.
